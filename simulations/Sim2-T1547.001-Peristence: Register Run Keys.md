## Executive Summary
* **Objective:** Simulate an adversary utilizing PowerShell to execute commands/scripts, ensure Windows 11 VM generates proper telemetry, and to confirm that Wash accurately triggers a high-severity alert for a value added to registry key.
* **Attack Overview:** T1547.001 Registry Run Keys is a classic persistence technique where an attacker configures Windows to automatically run their malware every time a specific user logs in.

## Defense and Hardening Recommendations (Mitigation)
* **Applocker/Application Control:** Configure an AppLocker path rule to deny execution of executable files (.exe) running out of C:\Users\*\AppData\Local\Temp\ and other user-writable directories. **Critical** During my simulation, I noticed that Windows natively allows standard users to write to HKCU keys. Because we cannot block the registry write without breaking user apps, AppLocker acts as our primary defense by blocking the actual payload binary from launching when the system reboots.
* **User Account Management (Least Privilege):** Ensure standard domain user accounts do not belong to the local Administrators group on the endpoint. **High** This is a critical defense-in-depth measure. Stripping admin rights completely isolates the attacker's persistence to the single user profile (HKCU) and blocks them from writing malicious entries to the machine-wide run keys (HKLM). 
* **Registry Permissions:** Modify Group Policy permissions to restrict write access to the system autostart pathways (such as HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run) strictly to the SYSTEM account. **Medium** This stops an attacker who has successfully escalated privileges from securing machine-wide persistence that affects every user.
* **Registry Auditing:** Enable Windows Security Policy registry auditing to capture Event ID 4657 (Registry Value Modified), and deploy Sysmon to monitor Event ID 13 (RegistryEvent). **High** Since we cannot easily block users from modifying their own HKCU hives, we must have strong detection logging to catch when an unusual or untrusted program path is written to a startup key.

## Customized Wazuh Detection Rule
Wazuh's default detection rules detected the basic PowerShell process creations, adversaries will place a program within a startup folder that will cause that program to execute when a user logs in. Due to this scenario, I created a custom Wazuh detection rule to target 'value added to registry key'.
